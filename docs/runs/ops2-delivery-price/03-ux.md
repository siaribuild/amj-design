# 03 — UX: delivery price and delivery address in ops2 (Revision 3)

Mock (owner gate): `docs/mocks/ops2-delivery-price.html`.
Spec: `01-spec.md` (49 criteria). Design: `02-design.md` rev 3 (anchors, endpoint,
migration). Rulings D1–D18 in `00-ask.md` are binding and win over anything here.

**Revision 3 supersedes revision 2 of this document entirely.** What changed:

- **D17** — the *card* is the door, not the Delivery row. `.rec-totals__row--door`,
  its hover wash, its focus ring, its per-row chevron and its `aria-label` are
  dead and are never built. The totals card becomes an `OpenablePanel`.
- **D18** — that card carries **no `<h2>`**; `OpenablePanel.title` becomes optional.
- **Criterion 19** — Project total no longer names the delivery absence. The amber
  `.rec-totals__absent` mechanism is deleted; the row prints the figure it has.
- Field limits and `line2` clearability follow design rev 3, not rev 2.

Everything below is decided. A developer implementing this makes no design calls.

## 1. Structure

| | Price | Address |
|---|---|---|
| Component | `DeliveryPricePanel.tsx` (new — sheet only; the door is the totals card, owned by `ProjectRecordPage`) | `DeliveryAddressPanel.tsx` (new — card **and** sheet) |
| Door lives | Lines tab, rail, **the whole `rec-totals` card** | Project tab, **first content**, above the `pq-empty` placeholder |
| Door markup | `OpenablePanel` with **no `title`**, `testId="record-totals"` | `OpenablePanel title="Delivery address"`, `testId="delivery-address"` |
| Door label | `Set the delivery price` (const `deliveryPriceDoor`, `record.ts`) | `Change the delivery address` (const `deliveryAddressDoor`) |
| Sheet | `SidePanel phoneForm="side" title="Delivery price" testId="delivery-price-sheet"` | `SidePanel phoneForm="side" title="Delivery address" testId="delivery-address-sheet"` |

| Gate | `record.delivery.editable` (server-derived, never re-derived in the UI) | same flag |

exists anywhere on the record (D9, criterion 20). No zone, no estimate, no note,

## 2. The totals card

### 2.1 What the card is

One `<section class="lp-panel lp-panel--door">` with a stretched
`.lp-panel__door` button, exactly like the line page's Price and Why cards. The
three rows stay plain `div.rec-totals__row`: **no per-row button, chevron, hover
wash, focus ring or `aria-label`** (criterion 16).

- **Hover:** one wash over the whole card (`.lp-panel--door:hover`, hover-capable
  pointers only — already in `panel.css`).
- **Focus:** one ring around the card (`.lp-panel__door:focus-visible`,
  `outline-offset: 2px`) — already in `panel.css`.
- **Keyboard:** one tab stop; Enter and Space both open (native `<button>`).
- **Chevron:** 16px, `--ds-text-muted`, right `--theme-spacing-md`, centred on the
  card's full height — `panel.css` needs no change for this feature.
- **Accessible name:** the door button's `aria-label` = `Set the delivery price`,
  from `record.ts`. The `<section>` gets **no** `aria-label` and the card renders
  **no `<h2>`** (criteria 18, 41).

Spacing: `.lp-panel` and `.rec-totals` share the same `sm md` padding, so the
card keeps today's metrics; only the chevron gutter (`--door`'s
`padding-right`) is added, which shifts the figures left by 16px + `sm`.
`.rec-totals` keeps its `font-size` and rows; its own card properties
(background, border, radius, shadow) come from `.lp-panel` instead and must not
be applied twice.

### 2.2 Row states

| row | state | renders | class |
|---|---|---|---|
| Lines | always | `money(lines)` → `$9,600`; with unpriced lines, the existing caveat ` · 1 with no rate` | `rec-totals__figure` / `rec-totals__caveat` |
| Delivery | settled (incl. `0`) | `money(amount)` → `$450`, `$0` — **whole dollars**, never `$450.00` | `rec-totals__figure` |
| Delivery | not settled | the literal **`Not set`**, muted, regular weight | `rec-totals__unset` (**new**) |
| Project total | always | `money(t.total ?? t.subtotal)` — a figure, always | `rec-totals__figure` |

Deleted with their mechanisms: `.rec-totals__missing` (the error-red
`no figure`) and `.rec-totals__absent` (the amber
`Delivery has not been set` / `N lines have no rate`). **Unpriced is the
ordinary state (D8)** and an explanation line under Project total is forbidden
(criterion 19). The Lines row's caveat stays as the one absence this card
names; `cornerFigure`'s header caveat is untouched.

### 2.3 Locked (D13, criterion 38)

`editable: false` → `OpenablePanel` receives no `open` prop. That alone removes
the chevron, the button, the tab stop and the hover wash. **No reason line, no
disabled styling, no tooltip.** The figures read exactly as they do when the
card is a door.

## 3. The price slide-out

Opens from the totals card. `SidePanel phoneForm="side"` — right-hand, 520px
(`min(88vw, 520px)`), at **every** viewport width including 375px (D2).

**Contents, in order:** one field — label `Delivery price`, `inputMode="decimal"`,
focused on open — and, in the footer, the save button. Nothing else. No zone, no
m², no destination echo, no estimate, no basis switch, no tax word in any state
(D11, criterion 22).

| state | field | footer |
|---|---|---|
| `delivery_amount` NULL (incl. an `unpriced_table` zone) | empty, placeholder `0.00`, focused | `Save delivery price` |
| settled at 250 | `250.00` (`amount.toFixed(2)`), focused, selectable | `Save delivery price` |
| saving | field unchanged | button `aria-busy`; a second press does nothing |
| refused (empty / non-numeric / negative) | `field--bad` border + message under the field | button stays pressable; **no request is sent** |
| save failed (network / 5xx) | typed value **kept** | `role="alert"` message above the button; panel stays open |
| dismissed (Done, backdrop, Escape) | discarded | — |

Refusal is **told, not implied**: the save button is never disabled in this
panel, and pressing it with an unacceptable value writes the message under the
field (criterion 27). Exactly one delivery figure is ever on screen (D12), and
no control anywhere in this panel produces `amount: null` — there is no clear,
revert or un-settle path in ops2 (D4/D16, criterion 25).

On success: PUT `{ amount: Number(value) }`, panel closes, the record re-fetches,
and the Delivery row and Project total update without a page reload
(criterion 26).

## 4. The delivery address card and slide-out

### 4.1 The card (Project tab, first content)

`OpenablePanel title="Delivery address"` — this card **keeps** its heading: on a
tab of unlike cards the title is what distinguishes it, unlike the totals card
whose rows name themselves.

Body: the stored destination as a stacked, comma-free block, in this order —

```
line1
line2
"Suburb STATE postcode"     ← the parts that exist, single-spaced
```

Absent parts **simply do not render** — no placeholder, no gap, no marker, no
"incomplete" badge (criterion 31). The everyday case today is one line:
`Craigieburn 3064`. All five columns NULL → one muted `Not set` line, and the
card is still pressable when editable.

Locked → no `open` prop: text only, no chevron, no tab stop, no reason line
(criterion 39).

### 4.2 The sheet

`SidePanel phoneForm="side" title="Delivery address"`. Five fields, one save:

| field | control | limit | may be emptied? |
|---|---|---|---|
| `Address line 1` | text input | 120 | no, once stored (D14) |
| `Address line 2` | text input | 120 | **yes** — clearing sends `line2: ""` |
| `Suburb` | text input | 80 | no, once stored |
| `State` | native `<select>` over the eight `AU_STATES` codes; blank option present **only** while no state is stored | — | no, once stored |
| `Postcode` | text input, `inputMode="numeric"` | exactly 4 digits | no, once stored |

Suburb, State and Postcode sit on one line at 520px (`1fr 8.5rem` grid for
State + Postcode, Suburb full width above them); they stack naturally in the
narrow panel.

Prefilled **from the project only**. The account holder's address never appears
— not as a value, not as a placeholder, not as a hint (criterion 33).

Save sends one PUT carrying only the fields that are present, and **never** an
`amount` key. The save button is disabled only when the body would be empty
(nothing typed, nothing stored). Refusals are field-level and send no request.
Changing the postcode re-resolves the zone server-side and **never** moves the
settled figure: no prompt, no banner, no recalculation notice, no delta
anywhere on any surface (D12, criterion 34).

Failure and dismissal behave exactly as the price sheet: dismissed edits are
discarded; a failed save keeps the panel open with the typed values and an
inline `role="alert"` message.

## 6. Component reuse — what is new and what is not

| component | change |
|---|---|
| `OpenablePanel` | `title` becomes optional (`title?: string`); no `<h2>` and no section `aria-label` when it is absent. Three edits, no new prop, no variant. Existing callers unchanged. |
| `SidePanel` | **no change.** Both sheets use `phoneForm="side"`, `dismiss="done"`. |
| `panel.css` | **no change.** The chevron is already card-centred and the door already stretches. |
| `record.css` | add `.rec-totals__unset`; delete `.rec-totals__missing` and `.rec-totals__absent`; reconcile `.rec-totals` padding against `.lp-panel` so it is not applied twice; add `.rec-addr` / `.rec-addr__unset`. |
| `PricePanel` / `WhyPanel` | untouched — `PricePanel` is the mechanical template for both new sheets, **minus its basis segment**, which must not be copied. |
| field styling | Ionic `IonInput labelPlacement="stacked"` and a native `<select>`, as elsewhere in ops2. No new form component. |

## 7. Accessibility

- One tab stop per door; Enter and Space both open (native `<button>`).
- Focus ring is drawn around the card, `outline-offset: 2px`, brand colour —
  never removed, never replaced by the hover wash.
- Opening moves focus into the sheet's first field; Escape, the backdrop and
  Done all dismiss through the same `onClose`.
- Field refusals are text under their own field and are announced by their
  input's `aria-describedby`; save failures are `role="alert"` in the footer.
- Hover is decoration only — it never carries the "this is pressable" meaning,
  because half this console's use is touch.
- `Not set` is muted grey on the page background: contrast ≥ 4.5:1
  (`--theme-neutral-500` on white). It is never red, never amber.
- Text nodes only on every address value — a `<script>` payload renders as
  literal characters (criterion 48).

## 8. Journeys the browser suite must walk

1. **Settle a price.** Record, editable, delivery NULL → card reads `Not set` →
   press card → sheet opens from the right → type `450` → Save → sheet closes,
   Delivery reads `$450`, Project total moves to `$10,050`, no reload.
2. **Correct a price.** Same, opening on `450.00`, saving `380`.
3. **Refuse.** `-40` → message, no request. Empty → message, no request.
4. **Fail.** Intercepted 5xx → panel open, `450` still typed, inline alert.
5. **Dismiss.** Type, press Done → nothing persisted, card unchanged.
6. **Keyboard.** Tab to the card, Space opens, Escape closes, focus returns.
7. **Locked record.** No chevron, no tab stop, no reason line, figures readable.
8. **Correct an address.** Project tab → card is the first content → press →
   five fields prefilled from the project → change suburb + postcode → Save →
   card updates, **the settled figure does not move**, no delta anywhere.
9. **Refuse an address.** Clear a stored suburb → message, no request. Clear a
   stored `line2` → allowed, saves, the line disappears from the card.
10. **Partial address.** Suburb + postcode only → one line, no warning, still
    pressable.
11. **375px.** Both doors press; both sheets arrive from the right, not from the
    bottom edge.
