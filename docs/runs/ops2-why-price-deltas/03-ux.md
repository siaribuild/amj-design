# 03 — UX: price deltas on the "Why this product?" ladder

Mock (the approval gate): `docs/mocks/ops2-why-price-deltas.html` — **revision 2**
Inputs: `01-spec.md` (AC1–AC20), `02-design.md` (the hand-off index),
owner feedback at the r1 mock gate, 2026-09-04.

This document is the contract for what gets built once the owner approves the

## 0. What revision 2 changed, and why

The owner rejected r1 on two counts and confirmed one state. All three are
settled here; §11 records the exchange so it is not re-litigated.

1. **"Information is organised into a single panel — it's difficult to read.
   Organise better. Panels. Lists (of panels), maybe? Don't give me a lazy
   solution."** The detail is no longer one scroll of headed blocks on one white
   field. It is the **line page's own shape**: the page ground carrying
   `lp-panel` cards, with the ladder as **one card containing a list of rows**.
   Nothing is re-implemented — `OpenablePanel`, `RowList`, `.lp-panel__lines`
   and `.ops2-row`'s hairline are the console's existing pieces, used by name.
   Three `wd__` rules are **deleted** as duplicates of them. §2.
2. **"On iPad there's a modal centred popup — that is NOT how our default
   slide-out panel works (REUSE COMPONENTS!!!)"** Correct, and it is a defect in
   `SidePanel` that predates this feature. Fixed in the shared component so
   every caller of the full-screen form is fixed at once. §7.
3. **"B2 — do we have a state like that or is it a new invention?"** Shipped
   behaviour, R11. No change. §11.3.

## 2. The screen, re-architected (owner ruling, r1 gate)

### The shape

```
┌ the panel's scrolling body — the PAGE ground, not card white ─────────┐
│  ┌ card ──────────────────────────────────────────────────────────┐   │
│  │ WHAT IT HAD TO MEET                                            │   │
│  │ Uw    ≤ 3.90   parsed from an energy report                    │   │
│  │ SHGC  ≤ 0.44   parsed from an energy report                    │   │
│  └────────────────────────────────────────────────────────────────┘   │
│  ┌ card (conditional blocks: comparison / split / bands) ─────────┐   │
│  └────────────────────────────────────────────────────────────────┘   │
│  ┌ card — rows reach its edges ───────────────────────────────────┐   │
│  │ WHAT ELSE WAS CONSIDERED                                       │   │
│  │ ░AMJ67 Awning · chosen                                        ░│   │
│  │ ░Uw 3.72 · SHGC 0.41 · met the caps                           ░│   │
│  │ ─────────────────────────────────────────────────────────────  │   │
│  │  AMJ67T Awning                                           +$65  │   │
│  │  Uw 3.41 · SHGC 0.39 · met the caps                            │   │
│  │ ─────────────────────────────────────────────────────────────  │   │
│  │  … three more …                                                │   │
│  │  The chosen product and the next four by rank. Each amount …   │   │

│  Nothing on this screen changes the quote — it is read and closed.     │
└───────────────────────────────────────────────────────────────────────┘
```

### Component reuse mapping — what replaces what

| Today in `WhyDetail.tsx` | Becomes | Note |
|---|---|---|
| `function Block({heading, testId, children})` — a local `<section class="wd__blk">` with an `<h3 class="wd__blk-h">` | **`OpenablePanel` from `../chrome/OpenablePanel`**, `title={heading} testId={testId}` and **no `open` prop** | `Block` is **deleted**. `OpenablePanel` renders exactly this section + title, plus `aria-label` — and openability is the *presence* of `open`, so a card that passes none is a container, never a door (R28 holds by construction). Heading level moves `h3` → `h2`, matching every other panel in the console. |
| `<dl class="wd__kv">` + `.wd__kv-row` | **`className="lp-panel__lines"`** with plain `<div>` children | `.wd__kv` was `.lp-panel__lines` re-typed with a narrower first column. One grid, one file. |
| `<ul class="wd__ladder">` | **`RowList` from `../chrome/RowList`**, `className="ops2-rows"` container it already owns | `RowList` is the list container only. Its sibling `Row` is **not** used — see below. |
| `<li class="wd__row">` | `<li className="ops2-row wd__row">` | `ops2-row` earns the `.ops2-row + .ops2-row` hairline from `rows.css`. Every other `.ops2-row` rule targets `> .ops2-row__open`, the pressable child this row deliberately does not have — so the class costs nothing and claims nothing. |
| `.wd__row-top` (flex, space-between) | **deleted** — the row is a grid | §3 |
| `.wd__card` bordered boxes inside the comparison block | keep the class, **drop the border**; the block's own card is now the only edge | A card inside a card is a card too many — the architect's ruling on the unit list (`rows.css`). The brand wash still says which side is the line's, and `.wd__who` still says it in words. |

> **`Row` is deliberately not reused.** `Row` renders a `<button class="ops2-row__open">` and requires `onActivate`. R28/AC20 forbid a pressable ladder row. Reusing the *container* and the *hairline* while declining the *button* is the whole of what is available here, and it is taken.

### The ladder is one card, not five

Five cards would give five borders to a set that is one idea. The rows belong to
each other: their alignment down the right-hand amount column is what lets one
downward scan answer *was it worth it?* — the question the estimator arrives
with. The card drops its inline padding so the rows and their hairlines reach
its edges (`.lp-panel--rows`), which is the rule the line page's unit list
already carries.

### Net effect on CSS

`.wd__blk`, `.wd__blk-h`, `.wd__kv`, `.wd__kv-row`, `.wd__ladder`, `.wd__row-top`
are all deleted; `.wd__row-meta`, `.wd__row-delta`, `.wd__row-delta--absent`,
`.lp-panel--rows` are added. **The stylesheet is smaller after this feature than
before it.** If the developer's diff grows `line.css`, something was
re-implemented rather than reused, and that is the failure this ruling is about.

## 3. The ladder row (D5 / AC19)

### Today

```
AMJ67T Awning                          Uw 3.41 · SHGC 0.39     ← .wd__row-top (flex, space-between)
met the caps                                                   ← .wd__row-verdict
```

Two facts on line one, one beneath. A third fact can only join line one, and at
375px the product name is what gives way — which fails AC19 directly.

### After

```
AMJ67T Awning                                            +$65
Uw 3.41 · SHGC 0.39 · met the caps
```

A two-column grid on the `<li>`:

| | Column 1 | Column 2 |
|---|---|---|
| Row 1 | product name (+ chosen mark) | the amount, right-aligned, baseline-aligned with the name |
| Row 2 | evidence: `figures · verdict` | — |

- **The name leads, alone, and is free to wrap.** It is the row's identity and
  the one string of unbounded length (a 36-character product name is real — mock
  frame C1). It must never truncate.
- **Figures and verdict merge into one clause.** They are one statement about
  one candidate: *Uw 3.41 · SHGC 0.39 · met the caps*. Merging them frees line 1
  for the amount without adding a third line.
- **The amount gets a column of its own.** Five amounts that shift with the
  length of the name beside them get read five times instead of once. A fixed
  right edge is what makes the ladder answer the question in one scan.

**The chosen row is tinted, not badged** — `--ds-color-brand-wash` on the `<li>`,
the console's existing "this is the one" treatment on a row. No new colour, no
new state; the words `· chosen` / `· the platform's pick` still carry it for a
reader who cannot see the tint.

## 4. The amount cell — every state

| Cell | When | Treatment |
|---|---|---|
| `+$65` | runner-up dearer than the chosen product (`deltaToSelected > 0`) | ink, semibold, tabular, explicit `+` |
| `-$200` | runner-up cheaper (`deltaToSelected < 0`) | identical treatment |
| `$0` | runner-up recorded at the same total (`deltaToSelected === 0`) | identical treatment, unsigned |
| `$---` | `deltaToSelected` is `null`, **or** the record predates price on the candidate contract | muted colour, regular weight |
| *(nothing rendered)* | the chosen row | no element, no placeholder, no reserved space |

Rules that follow:

- **Never coloured.** No green for cheaper, no red for dearer, no chip, no arrow
  glyph. Figures are not coloured anywhere in this console, and a green `-$50`
  beside a product that *failed its caps* turns an explanation into a
  recommendation — which R28 forbids. The sign carries the direction.
- **`$0` and `$---` must be tellable apart at a glance.** `$0` is a recorded fact
  (two products priced the same) and reads as ink/semibold like any amount.
  `$---` is the absence of a fact: muted, regular weight, and **not italic** —
  `.ops2-absent`'s italic applied to a run of dashes reads as damage rather than
  as absence.
- **Never `$0` for the uncalculable case** (AC5/D4), never a blank cell, never a
  hidden row.
- **The chosen row carries no amount at all** (AC4). It is the baseline the
  others are measured from; `+$0` would claim a direction that does not exist.
  The empty cell is made legible by copy, not by a placeholder — §5.
- **No date stamp, no "as at selection", no staleness hedge** on any row or near
  the ladder (AC8).
- **Nothing is pressable** (AC20/R28): no handler, no chevron, no hover state, no
  focus stop, no `<button>`. The only interactive element on the detail remains
  back.

### The money face

The amount uses this console's money treatment — **body face, semibold,
tabular** — matching `.rl-money` (`record.css:336`). It deliberately does **not**
use `.wd__fig`'s display face, which on this screen means "a thermal figure". A
dollar amount must never read as a Uw value.

## 5. Copy

### The ladder note — both branches change

The note under the ladder gains the clause that names what the amounts are
measured from. This is the sentence that makes the chosen row's empty cell
legible; without it a reader can conclude the value failed to render.

**Five rows (chosen + four runners-up)** — replaces the current string, which
ends "No price, nothing to price, and nothing here changes the line.":

> The chosen product and the next four by rank. Each amount is that product's
> difference from the chosen one, and nothing here changes the line.

**Fewer than five rows** — the existing sentence with the clause appended:

> {count} candidate{s} {was|were} recorded for this opening — the list is what
> exists, with nothing padded and no remainder counted. Each amount is that
> product's difference from the chosen one.

> **Deviation from `02-design.md`:** the design rewrote only the five-row branch.
> Without the second rewrite a three-row ladder shows amounts that nothing on
> the screen has explained. Both branches change.

The note renders in the ladder card, under the last row, as
`<p className="lp-panel__more">` — the panel's own footnote slot, not a fourth
copy of the muted-small treatment.

### Everything else — unchanged

`DETAIL.ladder` ("What else was considered"), `DETAIL.hadToMeet`,
`DETAIL.comparison`, `DETAIL.split`, `DETAIL.bands`, `chosenRowMark`,
`verdictWord`, `figuresText`, `DETAIL.closing` are all untouched. The
re-architecture moves headings into a different container; it does not reword
one of them.

### Banned vocabulary (AC7)

No copy added by this feature may contain: `gst`, `tax`, `inc`, `ex`, `incl`,
`excl`, `inclusive`, `exclusive`, `AUD`. That includes the aria-labels in §6 —
they are rendered text as far as the scanner is concerned. The strings above and
in §6 are already clean; keep them that way.

## 6. Screen readers

A bare `+` is the one part of this design that does not survive being read
aloud: most screen readers announce `+$65` as "sixty-five dollars", losing the
direction — which is the whole point of the figure.

Each amount carries a spoken label the eye never sees. The visible string is
unchanged.

| Visible | Spoken |
|---|---|
| `+$65` | `$65 dearer than the chosen product` |
| `-$200` | `$200 cheaper than the chosen product` |
| `$0` | `the same price as the chosen product` |
| `$---` | `no price difference was recorded` |

Implementation: `deltaLabel(delta: number | null, chosen: boolean): string | null`
beside `deltaText` in `whyCopy.ts` (same module, same reason — the node test that
scans copy for banned vocabulary sees it). Applied as `aria-label` on the same
`<span>` that carries the visible text.

> **Deviation from `02-design.md`:** the design named `deltaText` only. This adds
> one pure function beside it. Accessibility is on the "never be lazy about"
> list, and the cost is four strings.

## 7. The `SidePanel` full-screen form (owner's second rejection)

### The defect, precisely

`WhyDetail` renders through `SidePanel` with `phoneForm="screen"`
(`WhyDetail.tsx:46`). `SidePanel` sets `className={form === "side" ? "pq-sheet
pq-sheet--side" : "pq-sheet"}` — so both the `sheet` and the `screen` forms land
on the bare `.pq-sheet` class. `projects.css` styles `ion-modal.pq-sheet--side`
and **nothing else**: there is no rule anywhere in `src/ops2/` for the plain
class. The `sheet` form survives because Ionic's breakpoints size it; the
`screen` form falls through to Ionic's stock modal, which is full-bleed only on
a genuinely narrow phone and a **centred, rounded, inset card** from 768px up to
the `--cp-shell-rail` change point at 1024px. That band is the iPad.

The component's own comment calls `screen` *"full screen with no breakpoints"* —
true on a phone, false on a tablet. The documentation and the behaviour
disagree, and the behaviour is wrong.

### The fix — in the shared component, not in this feature's CSS

1. `src/ops2/chrome/SidePanel.tsx` — give the screen form a class of its own, so
   it is addressable without catching the bottom sheet:

   ```tsx
   className={`pq-sheet${form === "side" ? " pq-sheet--side" : ""}${form === "screen" ? " pq-sheet--screen" : ""}`}
   ```

   Update the `phoneForm` doc comment: the `screen` form is full-bleed at every
   width below the change point **because this stylesheet says so**, not because
   an unstyled `IonModal` happens to be.

2. `src/ops2/styles/projects.css` — beside the `--side` rules, so both forms of
   one component are in one place:

   ```css
   ion-modal.pq-sheet--screen {
     --width: 100%;
     --height: 100%;
     --border-radius: 0;
   }
   ion-modal.pq-sheet--screen::part(content) { box-shadow: none; }
   ```

   No media query: `form` already resolves to `side` above the change point, so
   the class only exists below it.

Constraints:

- **Above 1024px nothing changes.** The desk keeps its 520px right-hand
  slide-out, its 80% ink scrim and its 3px blur, exactly as it ships (mock
  frames B).
- **Do not "fix" this by switching `WhyDetail` to `phoneForm="side"`.** That
  changes what the surface *is* on a phone, which R26 settled, and leaves the
  defect in place for the next caller.
- **Do not touch `FilterSheet`.** Its `sheet` form is approved and shipped, and
  it keeps the bare `.pq-sheet` class it has today.
- The body inside keeps the console's `72ch` measure, left-aligned, exactly as
  `.ops2-page__body` does. It is not centred at tablet width — a second
  alignment rule for one surface is the kind of divergence this console has
  already paid for.

> `ponytail:` these rules live in `projects.css` because the `--side` rules
> already do. Move both to a chrome stylesheet when a third caller appears.

## 8. Files and the exact changes

### `src/ops2/projects/whyCopy.ts`

1. `deltaText(delta, chosen)` — as designed, with one correction: the returned
   string must carry the `$`. The design's snippet returns `+65`; AC2 requires
   `+$100` and AC5 requires `$---`. Correct form:

   ```ts
   export function deltaText(delta: number | null, chosen: boolean): string | null {
     if (chosen) return null;
     if (delta == null) return "$---";
     const r = Math.round(delta);
     const figure = `$${Math.abs(r).toLocaleString("en-AU")}`;
     return r === 0 ? figure : `${r < 0 ? "-" : "+"}${figure}`;
   }
   ```

   Whole dollars, `en-AU` grouping (`+$1,840`). `chosen` returning `null` is what
   produces "no element" rather than an empty one.
2. `deltaLabel(delta, chosen)` — new, per §6. Returns `null` when `chosen`.
3. `ladderNote` — both branches gain the clause, per §5.
4. The header rules list: the "D18 — no money, ever" line becomes the new rule —
   one delta per runner-up (D1 reversal); still no GST/tax/basis wording (D2),
   no totals, no second figure.

No formatting in JSX. Every string on this screen comes from this module.

### `src/ops2/projects/WhyDetail.tsx`

- Delete the local `Block` component; import `OpenablePanel` and use it wherever
  `Block` was used, passing `title` and `testId` and **never `open`**. All five
  test ids are preserved verbatim: `why-requirement`, `why-comparison`,
  `why-split`, `why-bands`, `why-ladder`.
- Import `RowList`; the ladder's `<ul>` becomes `<RowList className="ops2-rows"
  testId={…}>` (the class is `RowList`'s own default — pass no card chrome, the
  panel is already the card).
- The ladder card gets `lp-panel--rows` so the rows reach its edges. Because
  `OpenablePanel` owns its `className`, add the modifier there as an optional
  `className` prop on `OpenablePanel` — **one prop, appended, no mode flag** —
  rather than wrapping the panel in another element.
- Row markup:

  ```tsx
  const delta = deltaText(c.deltaToSelected, i === 0);
  …
  <li
    className={i === 0 ? "ops2-row wd__row wd__row--chosen" : "ops2-row wd__row"}
    key={`${c.productSlug}-${c.rank ?? i}`}
    data-testid="why-ladder-row"
  >
    <span className="wd__row-name">
      {candidateName(c)}
      {i === 0 && <span className="wd__row-mark"> {chosenRowMark(dto.selectionChanged)}</span>}
    </span>
    <span className="wd__row-meta">
      <span className="wd__row-figs">{candidateFigures(c)}</span>
      <span className="wd__row-verdict">{verdictWord(c, dto.requirement, dto.tolerance)}</span>
    </span>
    {delta !== null && (
      <span
        className={delta === "$---" ? "wd__row-delta wd__row-delta--absent" : "wd__row-delta"}
        data-testid="why-row-delta"
        aria-label={deltaLabel(c.deltaToSelected, i === 0) ?? undefined}
      >
        {delta}
      </span>
    )}

  ```

  The `--absent` class is chosen from the rendered string rather than
  re-deriving the null test — one source of truth for "this is not an amount".
- The ladder note moves from `<p className="wd__reason">` to
  `<p className="lp-panel__more">`.
- `Recorded` (the three non-recommendation kinds) gets the same card treatment
  automatically, because it composes the same `Block` call sites. Its headings,

## 10. `WhyPanel` — deliberately unchanged (the one open question)

The summary card's whole budget is three lines (R6/D20) and each answers *what*:
what it had to meet, what this one is, why it was chosen. The amounts answer
*why the others lost*, which is a five-row comparison and belongs with the five
rows. A single amount on the card would have nothing visible to be a difference
from.

`01-spec.md` §4 flags this as the owner's to veto. If he wants it on the card it
is one added line and AC1 extends there — say so at mock approval.

## 11. The r1 gate exchange, recorded

### 11.1 "Difficult to read — organise better" — accepted, §2

The r1 detail was one scroll of stacked blocks separated by headings. A heading
is not a boundary: at a glance it reads as one undifferentiated column, and
adding a price column made it worse, because a second column of figures then
competed for the same eye line. The console's own card vocabulary existed and
was not being used on this one surface — that was the defect.

### 11.2 "On iPad there's a modal centred popup" — accepted, §7

A pre-existing `SidePanel` defect, fixed in the shared component.

### 11.3 "B2 — do we have a state like that or is it a new invention?" — it is shipped

**R11**: *"When a human has changed the make-up, show both. The original platform
recommendation stays, unchanged, and a comparison of the human's selection
against the requirement is added beside it."* The DTO carries `current` alongside
