# UX — ops2 attention prefilter

Spec: `01-spec.md`. Design: `02-design.md`. Mock (the contract once approved):
`docs/mocks/ops2-attention-prefilter.html`.

Criterion numbers are the spec's. This document adds no structure the design did not
already decide; it fixes the copy, the states and the two markup/CSS details the design
left to this stage.

## 1. What the reader actually experiences

One sentence: **pressing an Attention row opens the queue on exactly the projects that row
counted, and the queue says so.**

The flow, end to end:

```
Attention                          Projects queue
─────────                          ──────────────
"1 ready to issue"   ──press──▶    strip: [Ready to issue]  Clear
                                   tabs:  All·1  Needs us·1  Customer·0
                                   list:  P-1031 — the one project that was counted
                                          │
                                   Clear ─┴─▶ default queue (Needs us), no strip
```

Three facts about that arrival the developer must not soften:

1. **The tab lands on `All`.** The predicate alone defines the set. `Awaiting payment` rows
   are waiting on the customer, so an intersection with the `Needs us` default would empty
   the list the row promised.
2. **The address is stripped after arrival** (the one-shot behaviour `?wait=` already has),
   so back-from-a-record does not re-apply a stale filter.
3. **The strip is the only thing on screen that explains the short list.** With `All` lit
   above a one-row list, a reader with no strip has no way to tell a filtered queue from an
   empty one — which is the class of defect this whole console exists to remove.

## 2. Screen-by-screen changes

### 2.1 Attention page (`src/ops2/attention/AttentionPage.tsx`) — no visual change

The rendered markup is identical to today: same groups, same order, same zero-suppression,
same row anatomy (`att-row__count` + `att-row__noun` + chevron). What changes is behind it:

| Thing | Today | After |
|---|---|---|
| Four project counts | `/api/ops/summary` | `selectProjects(rows, attentionQuery(key)).length` over `/api/ops/projects` |
| Four project hrefs | `/ops2/projects?wait=us` / `?wait=customer` | `/ops2/projects?attn=<row key>` |
| Enquiries / Trade rows | summary counts, own destinations | **unchanged** (P4) |
| Load states | one request | two, combined — see 2.2 |

Row copy is unchanged and stays as-is, including the singular/plural on submissions
(`1 new submission` / `4 new submissions`) and trade applications.

### 2.2 Attention load states

`combineLoads(summary, queue)`, precedence **unauthorised > error > loading > ready**.
Both sources must answer before the page is ready.

| State | Trigger | What renders |
|---|---|---|
| loading | either source still in flight, nothing shown yet | today's `attention-skeleton`, unchanged shape |
| unauthorised | summary returned 401/403 | today's `attention-error` panel, no retry |
| error | **either** source failed, or summary parsed degraded | today's `attention-error` panel, with **Try again** retrying *both* |
| ready | both answered | groups, zero-suppressed |
| empty | ready, every count zero | today's `attention-empty` panel, copy unchanged |

**Copy ruling — the error panel keeps Attention's own words, whichever source failed.**
`useProjectQueue` produces *"The queue did not load."* / *"The server answered 500…"*. That
is the Projects page's voice and it must not surface here. `combineLoads` maps a queue
failure onto Attention's existing strings verbatim:

> **Can't tell you what's waiting.**
> The counts didn't load, so none are shown. This is not an empty console — try again, or
> open Projects directly.

Criterion 15 is satisfied structurally: a count that could not be derived is never drawn,
so no row can be pressed claiming a set that was never counted.

### 2.3 Projects queue — arrival (`ProjectsPage.tsx`)

| Arrival | Query applied | Address | Strip |
|---|---|---|---|
| valid `?attn=<key>` | `attentionQuery(key)` — `chip:"all"`, no refinements, no search | replaced with `/ops2/projects` | shown, prefilter leads |
| unknown / injected `attn` value | `EMPTY_QUERY` | param stripped | **not** shown |
| re-enter with no `attn` while prefilter on (rail, back from a record) | `EMPTY_QUERY` | unchanged | not shown |
| any other route (bookmark, bare goto) | `EMPTY_QUERY` | unchanged | not shown |

An unrecognised value produces **no error panel, no message, and no echo** — it is
validated to `null` and discarded before anything renders. Indistinguishable from no
parameter at all (criteria 12, 22).

### 2.4 Projects queue — the active-filters strip

The existing `pq-active` strip, which until now appeared for funnel refinements only. It
renders when `query.attention !== null || activeRefinements.length > 0`.

```
┌──────────────────────────────────────────────────────────────┐
│ [Ready to issue]  + Unresolved lines                   Clear │   ← pq-active
└──────────────────────────────────────────────────────────────┘
```

- **The prefilter's name leads**, in the queue's existing card-chip recipe `.pq-flag` with
  a new `data-tone="brand"` — sage-100 wash, sage-600 text (5.2:1, passes AA at 12px).
  It wears the console's own "this is on" colour, the same sage as the active tab.
- **Refinements follow** as today's plain text, joined with ` + `, prefixed with ` + ` when
  a prefilter is also on.
- **One Clear.** With the prefilter on it applies `EMPTY_QUERY` — back to `Needs us`,
  refinements and search dropped with it (criterion 10). With refinements only it keeps
  today's refinements-only clear.
- The funnel bubble keeps counting refinements only. The prefilter is not a refinement and
  never appears in the filter sheet.

Chips stay live while the prefilter is on. Pressing one carries `attention` through, so the
reader narrows *within* the set the strip still names; the strip's Clear remains the one
exit (P6).

### 2.5 Projects queue — the new empty state

One new branch in `emptyStateFor`, after the no-rows branch and before search:

> **Nothing here is “Ready to issue” now.**
> These projects moved on after Attention counted them.
> `[ Back to Needs us ]` → `EMPTY_QUERY`

The headline interpolates the filter's own `label`, in curly quotes. Reachable only when
state changed between the gate rendering and the row being pressed (spec §3), so the detail
says *why* rather than blaming the reader's filters. The strip stays visible above it, so
the reader can still see what they asked for.

## 3. Component reuse map

Nothing new is built. Nothing existing changes shape.

| Need | Existing component / class | Change |
|---|---|---|
| Attention row | `chrome/RowList.tsx` `Row` (anchor form) | none — href value only |
| Attention error / empty / skeleton | `.pq-error` / `.pq-empty` / `.pq-skeleton` | none |
| Queue tabs, funnel, search | `.pq-chip`, `.pq-funnel`, `ion-searchbar.pq-search` | none |
| Queue list (both widths) | `ProjectCards` / `ProjectTable` | none |
| Active-filters strip | `.pq-active` | one wrapper span for the names; Clear becomes a query-applying button |
| Prefilter name | `.pq-flag` | one new tone |
| Queue empty | `EmptyPanel` + `emptyStateFor` | one new branch |
| Filter sheet | `FilterSheet.tsx` | **untouched** — the prefilter is not a refinement |

**New CSS — two declarations, both in `styles/projects.css`:**

```css
.pq-active__names { display:flex; align-items:center; gap:var(--theme-spacing-xs);
                    flex-wrap:wrap; min-width:0; }
.pq-flag[data-tone="brand"] { background:var(--ds-color-brand-subtle);
                              color:var(--ds-text-brand); }
```

No new stylesheet, no new token, no new radius. `.pq-flag`'s `RowFlag["tone"]` union gains
`"brand"`; the two existing card flags keep their tones.

## 4. States inventory

| Surface | Empty | Loading | Error | Long content |
|---|---|---|---|---|
| Attention | today's panel, copy unchanged | today's skeleton, now waiting on two requests | one panel for either failure, Attention's words, retries both | row nouns wrap to two lines rather than truncating (existing `.att-row` behaviour) |
| Queue, prefiltered | new branch, §2.5 | today's skeleton; the strip renders once ready, not during load | today's `queue-error`; **no strip and no tabs beside a failed load** (existing rule: a control that cannot do anything is the defect) | strip wraps at the names, `Clear` never shrinks; at 375 the longest label (*Awaiting payment*) fits beside Clear with room |
| Queue, unknown `attn` | default `Needs us` empty state, unchanged | unchanged | n/a — never an error | n/a |

Zero is absence, not a pressable row: a predicate matching nothing emits no Attention row at
all (criterion 14), and a group whose rows are all suppressed is absent entirely.

## 5. Copy — every string this feature touches

| Where | String |
|---|---|
| Strip, prefilter name | `New submissions` / `Being priced` / `Ready to issue` / `Awaiting payment` |
| Strip, joiner | ` + ` (between prefilter and refinements, and between refinements) |
| Strip, exit | `Clear` |
| Queue empty, headline | `Nothing here is “<label>” now.` |
| Queue empty, detail | `These projects moved on after Attention counted them.` |
| Queue empty, action | `Back to Needs us` |
| Attention failure, headline | `Can't tell you what's waiting.` *(existing)* |
| Attention failure, detail | `The counts didn't load, so none are shown. This is not an empty console — try again, or open Projects directly.` *(existing)* |
| Attention failure, action | `Try again` *(existing)* |

Attention row nouns, the queue's chips, the funnel's refinements, the search placeholder and
every card/table string are unchanged. No money string is added, removed or reformatted —
this feature touches no price and no GST display.

## 6. Accessibility

- The strip's prefilter name is **text**, not colour alone — it reads identically in
  greyscale, and the sage wash is redundant reinforcement (the console's standing rule).
- `Clear` is a real button with a visible name; no icon-only exit.
- Attention rows stay anchors: middle-click, Ctrl/Cmd-click and "copy link address" keep
  working, and the accessible name stays the full sentence (`1 ready to issue`).
- The chips keep `aria-pressed`; nothing here adds a `role="tablist"` claim.
- No focus is moved on arrival — the reader pressed a link and lands at the top of the
  destination, as with every other navigation in the console.

## 7. What this deliberately does not add

- No new ops control, no prefilter entry in the funnel sheet, no filter presets, no saved
  views, no "back to Attention" affordance (the rail and the browser both already do it).
- No count badge in the rail, no polling, no partial-failure rendering on Attention.
- The strip does not stick to the viewport on scroll: the sets it names are small by
  construction, and a sticky bar would cost a row of the list at 375.
