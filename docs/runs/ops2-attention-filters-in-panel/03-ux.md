# UX — ops2 Attention filters in the Projects filter panel

Spec: `01-spec.md` (criteria 1–21). Design: `02-design.md` (file index, sequencing).
Mock: `docs/mocks/ops2-attention-filters-in-panel.html` — **the contract once approved**.

Scope of this document: what is on screen, in what order, what every state says, and
which existing component renders it. It adds no control and no copy the mock does not
show. Where the design already names a file and a line, this document does not repeat it.

## 1 · What changes on screen, in one paragraph

The funnel panel grows from three checkboxes to six. Nothing else is added. Two things
are removed: the active-filters strip's sage prefilter pill, and the "this set moved on"
empty state. The funnel, its count bubble, the strip, the empty panel, the chips and the
search are untouched components rendering the same shapes over a larger refinement set.

## 2 · Screen by screen

### 2.1 The filter panel — `FilterSheet.tsx`, untouched

Rendered exactly as today: `SidePanel` (desk: 520px right-hand slide-out; phone: Ionic
bottom sheet at the 0.5 breakpoint), `IonList lines="full"`, one `IonItem` per control,
`IonCheckbox justify="space-between"` carrying the label and `<span class="pq-count">`.

**Order, top to bottom** (criterion 1, `REFINEMENTS`' own order — the panel renders
whatever it is handed, so the order lives in the model):

| # | Label | key | Count under the current query |
|---|---|---|---|
| 1 | New submissions | `submissions` | `selectProjects(rows, q + this).length` |
| 2 | Being priced | `inReview` | ditto |
| 3 | Ready to issue | `ready` | ditto |
| 4 | Awaiting payment | `awaitingPayment` | ditto |
| 5 | Unresolved lines | `unresolved` | ditto |
| 6 | In production | `production` | ditto |

Rules the mock pins:

- **No grouping.** One `IonList`, no heading, no divider, no second section, no radio
  anywhere in the panel. "Ready to issue" appears exactly once.
- **The count is always visible, including `0`** (criteria 3, 4, 11). It is muted
  (`.pq-sheet .pq-count`, `--ds-text-muted`) whether it reads 0 or 12 — a zero is not
  styled as an error, disabled, hidden or greyed differently. The control stays pressable.
- **A ticked control's count is what it leaves on top of everything else that is on**,
  so with all six ticked every count reads `0` and the list is empty. Same rule for all
  six; no exception for the four that arrived from Attention.
- Footer is unchanged: `Clear all filters` (disabled while `query.refinements` is empty,
  refinements-only when pressed) above the note *"Refinements narrow whichever quick
  filter is selected."*

### 2.2 The active-filters strip — `ProjectsPage.tsx`

Renders when `query.refinements.length > 0`. **Plain names only**, joined with ` + `, in
`REFINEMENTS` order:

```
New submissions + Unresolved lines                                    Clear
```

- The sage pill (`.pq-flag[data-tone="brand"]`) and the `+`-prefixed join are deleted,
  along with `attentionLabel`. An arrival-applied filter and a hand-ticked one are the
  same thing now, so they cannot look different.
- Names wrap to a second line at 375; `Clear` never wraps and never shrinks (existing
  `.pq-active__names` flex rules).
- **`Clear` sets `EMPTY_QUERY`** — chip back to `Needs us`, filters off, search cleared
  (criterion 8). One exit, one meaning, whether or not the reader arrived from Attention.

### 2.3 The funnel and its bubble — unchanged

Bubble = `query.refinements.length`, so it now ranges 0–6. Absent at 0. Accessible name
on the button stays `Filters, N active` / `Filters`; the bubble stays `aria-hidden`.

### 2.4 Arrival from Attention — unchanged to look at

`?attn=<key>` still applies chip `all` + the one mapped refinement + empty search, still
strips the param. The only visible difference from today is §2.2: the strip names the
filter in plain text instead of a pill.

## 3 · The flows

**F1 — Tick (criteria 5, 7).** Panel open → press a control → `onApply(control.query)` →
list narrows, strip gains the name, bubble increments. The chip and the search do not
move. The panel stays open, and every other control's count re-computes against the new
query (that is what makes a second tick predictable).

**F2 — Untick (criterion 6).** Same control → the pre-tick view returns, bubble
decrements, strip drops the name (and disappears at zero).

**F3 — The way back (criterion 9, the point of the feature).** Attention card → Projects
prefiltered → `Clear` → `EMPTY_QUERY` → funnel → tick the same filter → the same rows,
without leaving Projects and without a request.

**F4 — Leaving after an arrival (criterion 15).** Navigating away from `/ops2/projects`
after an arrival resets the query to `EMPTY_QUERY`; the return trip shows the unfiltered
queue with no bubble. Observably identical to today.

**No network on any of these** (criterion 20): every flow filters rows already in hand.

## 4 · States

| State | What renders | Copy |
|---|---|---|
| Panel, nothing on | Six controls with counts; `Clear all filters` disabled | Footer note unchanged |
| Panel, some on | Ticked controls first-class, counts re-computed; `Clear all filters` enabled | — |
| Filtered empty (any combination) | `.pq-empty`, filters **named**, way out offered | **"No projects match these filters."** / *"{names joined with ` + `} — nothing is left once these are on."* / button **"Clear filters"** (unticks filters, **leaves the chip and search alone**) |
| Ticked a `0` control under a chip (criterion 12) | The same empty state above. Chip is not moved, not widened, not reset | as above |
| Search stranded by a filter | Existing branch, unchanged | "Nothing matches “x” in this filter." / "N projects elsewhere in the queue — the filters are hiding them, not the search." / "Search all N projects" |
| No rows at all | Existing branch, unchanged, no clear button | "No projects yet." / "A project appears the moment a customer submits one." |
| Queue loading | Band holds its row with the control-row placeholder; list is the measured skeleton. No chips, no funnel — a filter over a list that has not arrived can do nothing | — |
| Queue failed | Single error panel with **Try again**. No control row | unchanged |
| `?attn=` unknown / hostile | Param stripped, no filter applied, unfiltered queue. No error, nothing echoed | — |
| **Attention "set moved on" empty** | **Deleted.** Falls through to the filters-named empty above | — |

Long content: six names is the maximum the strip can carry; the mock shows it wrapping to
two lines at 375 with `Clear` intact, and the empty state's detail line carrying all six.

## 6 · Accessibility

- Each control is a real checkbox whose accessible name carries the label **and** its
  count, so "Awaiting payment 0" is announced before it is pressed — the labelled zero has
  to work without sight, since it is the safety for leaving the chip alone.
- The funnel button's name stays `Filters, N active`; the bubble stays `aria-hidden` so
  the count is not read twice.
- Chips stay `aria-pressed` buttons — not tabs, no `role="tablist"`.
- Nothing on this surface depends on colour: every state is a word, and the strip's names
  are plain text after this change (one fewer colour-carrying element than today).
- Panel focus, dismiss (backdrop / Escape / Done) and the phone sheet's drag behaviour are
  `SidePanel`'s, unchanged.
