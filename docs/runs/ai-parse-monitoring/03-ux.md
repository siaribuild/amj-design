# ai-parse-monitoring — interaction spec

Stage 3 (UX). Sources: `01-spec.md` (28 acceptance criteria, binding),
`02-design.md` (architecture, binding). Mock for approval:
`docs/mocks/ai-parse-monitoring.html`.

This spec covers only what the developer would otherwise have to decide by
taste: layout, states, copy, and which existing component carries each part. It
adds no behaviour the spec and design do not already require.

---

## 1. What the screen is

The ops2 `/attention` route stops rendering `DestinationRoot`'s placeholder and
renders `AttentionPage`, which answers two questions in one glance:

- **Is the AI budget about to run out?** — credit balance, cap remaining.
- **Is parsing healthy?** — 7-day successes, 7-day errors, and the same numbers
  spread over days.

Every figure comes from the single KV snapshot the `*/10` cron writes. The page
makes no Cloudflare call, holds no threshold, and offers no drill-down (spec §3).

**Surface:** ops console, staff only. Density and speed over polish. Light
theme only — ops2 has no dark theme today and this page does not invent one.

---

## 2. Structure

```
OpsPage (existing frame — src/ops2/chrome/OpsPage.tsx)
├─ title      "Attention"
├─ identity   <p class="att-asat">      ← the freshness line, one per page
└─ children
   ├─ .att-grid
   │  ├─ .att-group  "AI BUDGET"            → Credit balance | Cap remaining
   │  └─ .att-group  "PARSING · LAST 7 DAYS" → Parses succeeded | Parses errored
   └─ .att-card.att-chart                    → 7 day columns, 2 bars each
```

Four tiles in **two named pairs**, not five loose cards. Each pair is one of the
two questions; the tiles under it are the two halves of that question's answer.
This is the whole reason the layout is not a row of anonymous boxes, and it is
what makes the page legible before any number is read.

### Widths

| | Desk (≥1024px) | Phone (<1024px) |
|---|---|---|
| `.att-grid` | 2 columns (one per group) | 1 column, groups stack |
| `.att-pair` | 2 columns | 2 columns — stays paired |
| Chart | full width, per-bar numerals shown | full width, numerals hidden |
| Freshness line | `identity` toolbar under the top bar | inside `.ops2-page__band` |
| Badge | `.ops2-bell__badge` in the existing bell button | `IonBadge` on the Attention `IonTabButton` |

The breakpoint is the console's single change point: `RAIL_MEDIA_QUERY`
(`(min-width: 1024px)`) via `useRailWidth()`. **Do not add a second media query
for it.** Per-bar numerals are hidden below that width in CSS only — two digits
over a 12px bar is a smudge, and the totals are already stated in the count
tiles a thumb-length above.

`OpsPage` is used with `width="full"` (the grid needs the full column, not the
72ch measure).

## 3. Component reuse

| Part | Existing thing | Change |
|---|---|---|
| Page frame, title, band, body | `OpsPage` | none — new props not needed; pass `title="Attention"`, `width="full"`, `identity={<AsAtLine …/>}` |
| Freshness line slot | `OpsPage` `identity` prop (already used by the record) | none |
| Card surface | `.ds-surface-card` recipe values | `.att-card` composes the same three declarations plus its own layout |
| Red card treatment | shape of `.rec-refusal` (record.css) | `.att-card[data-state="red"]` — error wash, 1px full error border, error ink |
| Section labels, card labels | `.ds-type-label-md` | `.att-group__label` / `.att-card__label` use the same size/tracking/case |
| Money figures | `.rec-ident__money strong` (display face + tabular-nums) | same treatment in `.att-card__figure` |
| Empty state | `.pq-empty` (projects.css) | reused verbatim |
| Error state | `.pq-error` (projects.css) | reused verbatim, plus a "Try again" button |
| Loading | `.pq-skeleton` vocabulary | `.att-skeleton` blocks placed in the real layout boxes |
| Bell button | `OpsPage.tsx:173–180` | add `<span class="ops2-bell__badge">` child, rendered only when count > 0; extend `aria-label` |
| Phone tab | `Ops2App.tsx:272–289` Attention `IonTabButton` | add `<IonBadge color="danger">` child, rendered only when count > 0 |

**New stylesheet:** `src/ops2/styles/attention.css`, imported from
`src/ops2/styles/index.css` after `record.css`. It may name only `--ds-*`
tokens — no palette steps, no `--ion-color-step-*`, no `--ion-text-color-rgb`
(that pattern is absent from ops2 on purpose; quiet roles use
`--ds-text-secondary` / `--ds-text-muted`).

Radii stay at `--ds-radius-surface` (5px) for cards and `--ds-radius-control`
(3px) for the small stuff. The bar caps are 2px, the badge is a pill — both are
shapes, not surfaces, and neither reads as a rounded card.

## 4. Cards

### 4.1 Credit balance (criterion 1)

- Label: `Credit balance`
- Figure: `$42.18` — the snapshot's balance, USD, formatted to 2 decimals.
- Note: `Floor $5.00 · USD, as Cloudflare reports it` — the floor comes from
  the snapshot, never hardcoded in the component.

### 4.2 Cap remaining (criterion 2)

- Label: `Cap remaining`
- Figure: cap minus billed spend, e.g. `$11.60`.
- Note: `$8.40 of the $20.00 gateway cap used (42%)` — spend, cap and
  percentage all from the snapshot.
- The label says *remaining* because the figure is headroom; the note carries
  the percentage because the red ceiling is a percentage.
- The snapshot's cap-source label (`gateway` | `account`, criterion 3) appears
  as the word before "cap": `gateway cap` or `account cap`. That is the whole
  surfacing of criterion 3 — no separate badge, no tooltip.

### 4.3 Parses succeeded (criterion 7)

- Label: `Parses succeeded`, preceded by an 8px sage `.att-key` square.
- Figure: `38`, thousands-separated above 999.
- Note: `One parse = one job claim`

### 4.4 Parses errored (criterion 7)

- Label: `Parses errored`, preceded by an 8px red `.att-key` square.
- Figure: `3`
- Note: `Failed, or stuck over 30 minutes`

**The error card is never painted as an alarm.** Its figure is ink, its card is
white. v1 has one notification condition and it is the budget (criteria 15–17);
a red error card would claim an alarm that does not exist, and the spec has no
amber tier (§3). The red on this card is a **key square** — 8px, tied to the
chart's error series — a data hue, not a state.

The two key squares are also the only thing that makes a card and its bars read
as the same fact rather than two numbers that happen to agree.

## 5. Chart (criteria 13, 14)

Plain divs and CSS heights. Fourteen numbers do not earn a chart library, and
the design already forbids one.

- 7 columns, oldest → newest, left → right. The last column's label is
  `Today`; the rest are `Thu 28`-style (weekday + date) at desk, weekday only
  (`Thu`) on the phone.
- Days are Australia/Melbourne calendar days (spec §4 assumption), which the
  snapshot already bucketed. The page does no date maths.
- Two bars per column: success (sage) then error (red), 6px apart, 16px wide at
  desk / 12px on the phone.
- Bar height = `value / max(all values in the window) * 100%` of a 120px plot
  (96px on the phone).
- **A zero day draws a 2px stub** in `--ds-border-default` (criterion 14: a
  zero day is a zero bucket, not a missing day — the column, its label and a
  visible baseline stub all stay).
- Per-bar numerals sit above each non-zero bar at desk width; zero bars carry no
  numeral (the stub says zero, a "0" floating over nothing is noise).
- Legend: `Succeeded` / `Errored` with the same two key squares, top-right of
  the chart card.
- Baseline: 1px `--ds-border-default` under the columns. No gridlines, no
  y-axis — the numerals are the axis at desk, and the totals are on the cards.

### Chart empty state (criterion 12)

Zero parses across the whole window renders, inside the chart card, in place of
the plot:

> **Nothing parsed in the last 7 days**
> Parsing runs when a customer uploads. No uploads, no parses.

…and **the 7 day labels stay below it**, so the window it is talking about is
still visible. Not an error, not a blank box. The count cards show `0` in this
state (a real zero, from D1).

## 6. States

### 6.1 Freshness (criterion 6)

One line in the `identity` slot, at both widths:

- Fresh (≤30 min): `As at 14:20 · refreshes every 10 minutes` — muted, no icon.
- Stale (>30 min): `Not refreshed since 12:10 — 2 h 10 m ago. The 10-minute job
  may have stopped.` — `--ds-color-warning-text`, weight 500, warning triangle.
  On the phone the sentence truncates to `Not refreshed since 12:10 — 2 h 10 m
  ago`.

**Stale also stamps every card** with `as at 12:10` in
`--ds-color-warning-text` (`.att-card__stamp`). That is criterion 6 literally —
each card states the age — and it appears *only* when stale, so a healthy page
does not repeat one timestamp five times. Figures are still shown when stale;
an old number labelled old beats an empty page (spec §4).

Age formatting: `< 90 min` → `Nm ago`; otherwise `Nh Nm ago`; over 24h →
`Nd ago`.

### 6.2 Red (criteria 16, 17)

Only the money cards can be red, and only from the snapshot's precomputed `red`
flags — the page never compares a number to a threshold.

- Balance below floor: figure red, note becomes
  `⚠ Below the $5.00 floor` (warning triangle icon + text).
- Cap used above ceiling: note becomes `⚠ 86% of the $20.00 gateway cap used`.
- Card: `--ds-color-error-subtle` background, 1px `--ds-color-error` border.
  No thick left edge, no coloured slab, no banner repeating it at the top of the
  page. The figure is the loud thing, because the figure *is* the fault.
- Both conditions red at once still renders as two red cards and **one**
  notification (`1` on the bell / tab) — one source, one notification.

### 6.3 Money unavailable (criteria 4, 19)

- Figure: `—` (em dash) in `--ds-text-muted`. **Never `0`, never red.**
- Note, by cause:
  - no token configured → `Unavailable. No Cloudflare token configured`
  - call failed/timed out → `Unavailable. Cloudflare did not answer at 14:20`
- Count cards and chart render their D1 numbers as normal.
- Badge count is 0. An unknown number cannot raise an alarm.

### 6.4 No snapshot yet

KV has no snapshot (first deploy, before the cron's first tick). Whole body is
`.pq-empty`:

> **No figures yet**
> The monitoring job writes them every 10 minutes. If nothing appears by the
> next tick, the cron is not running.

Not an error state — nothing has gone wrong yet, and the copy says what to
conclude if it stays.

### 6.5 Loading

Skeleton blocks in the real layout boxes — same cards, same grid, same seven
chart columns — so nothing shifts when data lands. Body carries
`aria-busy="true"`. No spinner (criterion 5: no spinner that never resolves).

### 6.6 Fetch failed

`GET /api/ops/monitoring/snapshot` did not answer (a 5xx or network failure —
a 401/403 is handled by the existing ops2 guard, not here). Whole body is
`.pq-error`, `role="alert"`:

> **Couldn't load the monitoring figures**
> The console reached the server but it did not answer. Nothing is wrong with
> parsing itself.
> `[ Try again ]`

The second sentence matters: a monitoring page failing to load reads as
"parsing is broken" unless it says otherwise. "Try again" refetches the
endpoint; it does not trigger the cron.

### 6.7 Long content

- Counts thousands-separated (`1,284`); the figure size holds 5 digits at
  375px inside a half-width tile.
- Money holds `$1,234.56`. Beyond that the figure wraps rather than shrinks —
  no font-size juggling.
- Notes wrap to a second line; cards in a pair are grid items so both grow
  together and stay bottom-aligned.

## 7. Notification badge (criteria 15–19)

The count comes from `notificationCount()` over the source list — the page and
the badge read the same snapshot, so they can never disagree.

- Count 0 → **nothing is drawn**. No empty circle, no dot, no `0`.
- Count > 0 → the number, white on `--ds-color-error`, min 16px pill, 10px
  tabular numerals.
- Desk: absolutely positioned top-right inside the existing `.ops2-bell`
  button, with a 2px card-coloured ring so it stays legible over the icon.
  `aria-label` becomes `Attention — 1 item` (`{n} items` for n > 1).
- Phone: `<IonBadge color="danger">` inside the Attention `IonTabButton`; Ionic
  positions it. The tab's own label is unchanged.
- Tapping the bell already navigates to `HOME_PATH` (`/attention`) — criterion
  18 needs no new handler, only the badge.
- The badge appears on **every** ops2 page, because the bell and the tab bar are
  chrome. That is criteria 16/17's "any ops2 page".

Adding a second source later changes neither the badge markup nor the
aggregation (criterion 20) — it appends to the array in
`src/ops2/notifications/sources.ts`.

## 8. Accessibility

- Section labels are real `<h2>`s, card labels `<h3>`s, under `OpsPage`'s `<h1>
  Attention`. Heading order is unbroken.
- Colour is never the only carrier: red cards state the fault in words
  (`Below the $5.00 floor`), the stale line states the age in words, and the two
  chart series are named in the legend *and* in the card labels beside their key
  squares.
- Chart: the plot is `role="img"` with an `aria-label` naming the window and
  both totals (`Successes and errors per day for the last 7 days; 38 succeeded,
  3 errored`). Per-day figures are already in the DOM as text at desk width;
  the phone hides them visually only (`display:none` is not acceptable for the
  numerals if they are the only textual source — on the phone the `role="img"`
  label carries the totals, and the day detail is deliberately not a phone
  task).
- Contrast: error text is `--ds-color-error-text` (`#82261d`) on
  `--ds-color-error-subtle`, and warning text `--ds-color-warning-text`
  (`#624410`) — both well past 4.5:1. The 8px key squares are decorative
  (`aria-hidden`), so their contrast is not load-bearing.
- Bars carry no focus and no tooltip: the page has no drill-down (spec §3), so
  nothing here is interactive except the "Try again" button and the existing
  chrome.
- Reduced motion: there is no motion on this page. Nothing animates in, bars do
  not grow.

## 10. Phone (375px) specifics

- Groups stack; tiles inside a pair stay side by side.
- Card labels shorten inside the money pair (`Credit`, `Cap left`) and the
  count pair (`Succeeded`, `Errored`) — the group label above already supplies
  the noun. Desk uses the full labels.
- Figure drops from `--fs-3xl` to `--fs-2xl`; card padding from
  `--sp-md --sp-lg` to `--sp-sm --sp-md`.
- Chart keeps all 7 days, drops numerals, 96px plot.
- Tab bar unchanged apart from the badge.

## 11. Out of this screen

No click-through from any card, no per-error rows, no dismissal, no refresh
button beyond the error state's "Try again", no amber tier, no dark theme, no
customer surface. All of these are spec §3.

---

## 12. Decisions the mock puts to the owner

1. Two named pairs, not five loose cards.
2. One freshness line in the band; per-card stamps only when stale.
3. "Cap remaining" as the label, with percentage-used in the note.
4. Errored parses are never painted as an alarm — only the budget goes red.
5. Chart numerals at desk, hidden on the phone.
6. No dark mode.

Accepted tweaks from the approval round get folded back into this document
before the build starts; the approved mock is the contract.
