The overall cron → KV snapshot → staff endpoint → UI shape is sound, but I would not approve the architecture yet.

1. **High — “last 7 days” has no coherent contract.** [parseWindowStart](/E:/Projects/amj-website-design/src/data/monitoring.ts:95) starts at Melbourne midnight six dates ago, producing a 144–168-hour window—not the rolling 7×24 hours specified in [02-design.md](/E:/Projects/amj-website-design/docs/runs/ai-parse-monitoring/02-design.md:115). A rolling window spans parts of eight calendar dates, so the stated seven-bucket model cannot represent it. The implementation silently chose calendar days to keep cards and chart consistent. Explicitly choose either seven Melbourne calendar dates or rolling 24-hour buckets and align the contract.

2. **Medium — the shared core does not provide the shared interface it was created for.** [parseMonitoringSnapshot](/E:/Projects/amj-website-design/src/data/monitoring.ts:9) returns `unknown`; the client redeclares both snapshot types in [useMonitoring.ts](/E:/Projects/amj-website-design/src/ops2/attention/useMonitoring.ts:5), while client and worker recover the shape through casts. Validation of the wire snapshot is consequently split between modules. Export typed stored/wire snapshot parsers from the core so callers cross one real seam without `as any` or duplicate contracts.

3. **Medium — polling is shared at the fetch level, but owned per rendered page.** Every [useNotificationCount](/E:/Projects/amj-website-design/src/ops2/chrome/useNotificationCount.ts:37) instance creates its own interval, while both the shell and [OpsPage](/E:/Projects/amj-website-design/src/ops2/chrome/OpsPage.tsx:100) mount it. Ionic can retain routed pages, allowing timers and subscribers to accumulate. The TTL coalesces network calls but not timers or hidden-page updates. The module-level store should own one polling loop, started by its first subscriber and stopped after its last.

4. **Low — monitoring failure is collapsed into “healthy zero.”** Non-2xx, malformed payloads, and network failures return `0` in [useNotificationCount.ts](/E:/Projects/amj-website-design/src/ops2/chrome/useNotificationCount.ts:22); malformed stored JSON can also throw before reaching the strict parser in [worker/lib/monitoring.ts](/E:/Projects/amj-website-design/worker/lib/monitoring.ts:152). This makes an unavailable monitoring path indistinguishable from no active notification. Preserve last-known state or expose an unavailable/stale status, and contain JSON decoding at the KV seam.
