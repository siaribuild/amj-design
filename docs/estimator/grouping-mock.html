Estimator list — separating a record from its parts

Four treatments of the same data, drawn with the live design tokens, type scale and column tracks. The goal in each: make it obvious where one opening ends and the next begins, and that W1A/W1B belong to W1.

Rows show the CURRENT build — a composite reads “Composite Window”, carries no chip, and its icon is drawn from its units. Your sketch predates those changes. W4 is deliberately shown with a blocked unit so each option can be judged with a state stripe in play.

Three defects the review turned up, independent of which option you pick

  1. Column headers are 6px out of register. The header strip uses px-4 while rows use md:px-2.5 from 768px up, so every label sits 6px left of the column it names. This mock uses the row’s padding for both, which is why its headers line up and the live page’s don’t.
  2. The connector’s end-cap rule never matches what it means. .quote-unitrow:last-of-type — but each unit is wrapped in its own <div>, so it matches every collapsed unit and no expanded one.
  3. The only non-visual cue that a unit belongs to its opening is in the wrong place. The “Included in W1” string is the row’s last node, so it is announced after all the data it qualifies, and never at all when tabbing.
A · today

Continuous table, hairline per row

One frame, one divider weight everywhere. A unit is distinguished by indent, connector and the recessive fill — but the parent sits on paper like every unrelated row, so it does not read as the head of anything.

Where it falls short: every boundary carries identical weight, so “end of W1’s units” and “start of W2” look the same. That is exactly the complaint.

B · your sketch

One bounded card per opening

Each opening becomes a card; its units sit inside it; the header stays outside and still governs the columns.

OpeningStatusProductSizePrice

What the review found: the card genuinely helps in one way nobody expected — it puts the parent inside the group it heads, which A never does. But look at W4: the 1px card border sits outboard of the 3px state stripe, giving 4px of doubled edge — the exact thing .quote-row’s comment forbids. State is per-row while a border is per-record, so a record whose parent and unit disagree has no honest border colour. And a composite nests four fills (bone → paper → recessive → recessive), against the rule that past three levels the answer is a rule, not another tint. Cost: +13% scroll at this gap, +37% with card padding.

C · recommended

Gap between records, rail through the group

No borders and no wrapper. A gap separates records; within a record there is no divider at all; and the connector’s vertical arm extends up through the parent, so a composite reads as one bracketed group headed by its opening.

OpeningStatusProductSizePrice

Why this one: it gets the card’s real benefit — the parent visibly heads its group — without a border to collide with the state stripe, without a fourth tint, without a wrapper element, and without the columns desyncing from a header left outside. A gap is also the one cue that survives zoom, greyscale and a daylit site-office monitor. Cost is roughly a third of B’s.

D · cheapest

Graded dividers only

Keep the table exactly as it is; give the boundary between openings the stronger hairline and remove the one within a composite. Zero extra pixels.

OpeningStatusProductSizePrice

Trade-off: costs nothing and reads well on this screen. But it asks an 18%-black hairline to be told apart from a 28%-black one — a distinction that flattens under zoom, greyscale, or a cheap monitor in daylight. If the complaint is “I can’t tell where a record ends”, a cue that is sometimes imperceptible is a partial fix.
