ops2 R1 — the frame and the record

Rework on the plane shell (ADR 0004). Every frame below is the same console, mounted at a different width. All of them are live — tap through them. The phone frames are the design; the wide frames are the same zones revealed.

The growth law — two moves, and only two.
1. A zone that was a plane becomes a pane. Which zones are simultaneous is the width class's only structural decision.
2. A push that was a plane becomes a disclosure in place. Same row, same route, different arrival.
Nothing is rearranged and no content changes zones at any width. A zone always reads its own measured width, so a 380px pane on a desktop folds exactly as a phone does — which is why revealing a zone never assumes it got wide (C1: the Fold, open, with apps beside it).

1 · The phone — the whole design, at the floor and at reference width

Three zones (index · work · edit) and a bounded push stack. Nothing is a long scroll: at job scope the work zone is a push-row list, not a stack of blocks. Every plane is identity band → scrolling body → footer, with the footer sticky inside the plane's flex column, never viewport-fixed.

Its own 48px identity band — not the job bar. ‹ 4/18 › steps the filtered set without returning to the list. That is what makes a phone a review device.

2 · Growth — the same zones, revealed

No layout is re-authored. index is the Lines plane, then an overlay list, then a 48px code strip, then a full rail. work is the ground at every width. edit is a pushed plane, then a right sheet, then a persistent pane. The rail yields; the pane never does (R-13) — which is why the live totals loop survives down to 1024.

768 × 1024 — tablet portrait
One ground zone; index and edit are summoned. Tap Lines · 18 in the header for the overlay list. The back control persists.
1024 × 720 — compact
Zones become simultaneous. The rail compresses to the 48px code strip so the editor can stay a column — the rail yields, never the pane.
1440 × 860 — desktop
Full rail · canvas · pane, plus the persistent 224px nav. Density rises through row tokens, not through a different IA. AC-14: the openings list and the work content are usable at once, and no primary column sits at a phone measure.

3 · The states that matter

Four distinct pictures, never one (R-161). Loading is never failure; failure is never a spinner; both differ from an empty filter and from a gate. Every one carries a way forward.

390 — loading
A skeleton of the shape that is coming; layout reserved. Never a bare or full-viewport spinner.
390 — failed read
A bordered card in the zone that failed, with the code and Retry. Navigation still works — the failure is the zone's, not the frame's.
390 — no lines
Delete-to-empty is allowed (AC-99). The issue primary is disabled with its reason — visible, never hidden.
390 — read-only (issued)
AC-81: no editor, no add, no delete; the bar names the real cause. One line and a route back — never a form full of disabled inputs.
390 — save failed at the control
AC-20/21/22: the error renders at the control that failed, the typed values stay on screen, and Retry re-sends the same payload. No toast — there is no toast system.
