1 · The primary action, refused

Today the disabled Issue reviewed quote is card-white with an error-red border and error-red text. Red is for destructive and error; a refused control is neither — but the problem the red was solving is real, and Ionic's default (a flat grey wash at opacity:.5) reads as a line of text in a toolbar. Both candidates below keep the button's shape and weight and drop every error semantic: sunken fill, secondary ink at full opacity — 4.75:1, above the 4.5 floor. The error family stays on .rec-refusal, which is what P1-AC-39 actually asked for.

They differ in one value: the edge. FB-AC-30 asks that the control be distinguishable from the toolbar by its fill or its border. The sunken fill is 1.10:1 against the white toolbar — it cannot carry that on its own, so the border has to. --ds-border-strong (#b5b2ab) measures 2.12:1 against the toolbar and 1.92:1 against its own fill, both under the 3:1 floor for a control boundary; at those numbers the named regression returns in beige rather than grey. --ds-text-muted (#8b8880) is 3.54:1 and 3.22:1 and is still the quietest ops2 token that clears 3:1 — no --ds-border-* token does on white. Nothing else about the control changes. Owner picks.

2 · One row, one list — every state

One .ops2-row and one .ops2-rows serve the queue's phone card, the record's line list and the line page's unit rows. The defect (FB-AC-1) is the last pair below: today the flag edge is an inset shadow on the <li> and the hover wash is a background on the <button> inside it, so hovering paints the edge out. Both move onto .ops2-row__open — the single pressable — and an inset shadow always draws above its own element's background, so no state can erase another. Hover states are shown here as static classes.

3 · "Why this product" — the door is always there

For unresolved, unrecorded and human the API returns only the line's own figures — no requirement, no candidates. Nothing new is fetched. The panel now carries a chevron and a door on every kind, and the detail keeps its three headings and names each absence instead of hiding the block — never a dash, never a zero.

An absence is a sentence someone has to read, so it is readable text: italic, at --ds-text-secondary, 5.23:1 on card. It was drawn at --ds-text-muted — 3.54:1, the exact value the approved mock's rule A1 rejects by name. Where an absence fills a whole section it sits in a sunken slot with the row's 3 px leading mark, so the section reads as one someone filled in. That is the difference between a screen that is complete-and-empty and one that looks broken, and it is what the unrecorded detail below is asking you to approve.
