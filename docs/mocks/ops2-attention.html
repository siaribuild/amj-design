ops2 — Attention

The console's gate and its landing screen: which area needs a person, and how much is waiting behind each door. Not a metrics page, and never a working area — a row leads, it never acts. There is no approve, no assign, no dismiss and no mark-read anywhere on this screen.

Everything is drawn from what the console already has: OpsPage's frame and its <h1>, the one RowList/Row, and the queue's own .pq-empty / .pq-error / .pq-skeleton treatments. The only new CSS is the group heading (about ten lines).

1 · Desk, 1440 — everything waiting

Three groups, one per destination that has work. Group order is fixed — Projects, Enquiries, Customers — so a group appearing or vanishing never moves the ones above it. Inside Projects the counts read in lifecycle order. The number leads every row, so the screen answers from a standing start. Enquiries is a new destination in the rail (dashed, below).

3 · Nothing waiting — and the two ways that could be a lie

This is the screen's whole integrity. “Nothing is waiting” is only ever said when the console actually counted and the answer was nought. If the counts could not be read — the request failed, or the endpoint answered degraded — the screen says so and shows no counts at all, not even ones that might be right. The two failures are indistinguishable to the reader on purpose: both mean “I cannot tell you”.

4 · What a press does

Every row is a door, and lands somewhere the work is actually visible. The four Projects rows open the queue with the wait filter that count belongs to already lit — exactly the screen the reader would have by tapping that chip themselves, and All clears it back to the whole queue. The count and the list it opens cannot disagree, because both answer the same question.

6 · Row states — pointer and keyboard

Nothing new: the console's one row component already owns hover, press and focus, and Attention adds no state to it. No leading edge on these rows — that mark stays reserved for the “critically wrong” kind of item, the day a source for it exists.

Top: rest. Middle: hover / press wash. Bottom: keyboard focus ring, inset so it draws against the row's own edge rather than over the hairline it shares. Each row reads to a screen reader as one link — “4 new submissions” — under its group's heading; the whole screen is one <h1>, three <h2>s and a handful of links.
