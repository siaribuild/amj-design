ops2 — Attention prefilter

One change, said in one sentence: pressing an Attention row opens the queue on exactly the projects that row counted — not on the broad “waiting on us” set it lands on today. The number and the list come from one selector, so they cannot disagree.

Nothing is added to the Attention page's look and no control is added to the queue. The only new thing on screen is the queue's existing active-filters strip, now naming the prefilter and offering the one way back. Two new CSS declarations in total, both marked in the stylesheet above.

The six projects every frame below is drawn from — the design's own fixture, shaped so the four predicates give non-empty, non-identical sets:

1 · Attention, desk 1440 — unchanged to look at

Same rows, same order, same zero-suppression. What changed is underneath: the four project counts are now selectProjects(rows, attentionQuery(key)).length over the same /api/ops/projects the queue reads, and each row's link carries ?attn=<key> instead of the broad ?wait=. Enquiries and Trade are untouched — summary counts, their own destinations.

Keyboard focus is shown on 1 ready to issue — the row is an anchor, so it is still middle-clickable and copyable. Its href is now /ops2/projects?attn=readyToIssue. The row's own key is the parameter value: one vocabulary, not a translation table.

2 · The press — the queue opens on the one project that row counted

The strip above the list is the queue's existing pq-active escape strip, which until now only appeared for funnel refinements. It names the prefilter in the sage chip and carries the one way out. The tabs stay live and their counts are honest within the filtered set: All · 1 because the set is one project. The address is stripped after arrival — the one-shot behaviour ?wait= already has, so coming back from a record does not re-apply an old filter.

6 · The states that are not a filtered list

Four, and each says something different. Two are new copy; two are today's panels, shown because the Attention page's failure now covers the projects request as well.

a · the set emptied between the count and the press — new copy

Ready to issue
Nothing here is “Ready to issue” now. These projects moved on after Attention counted them.

Reachable only when a colleague issued the quote in the seconds between the gate rendering and the row being pressed. It says why rather than blaming the filter, and the strip stays so the reader can see what they asked for.
