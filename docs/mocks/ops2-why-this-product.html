Why this product — ops2

Phase 2 (the shared full-screen drawing viewer) and Phase 3b (the panel and its detail slide-out). Every state is drawn, not just the happy one — most of the rulings are about what shows when something is missing.

What this mock holds itself to
  • No money and no GST anywhere on this surface — R10, and the house rule.
  • No certification anywhere, in any phase — R5.
  • No excluded candidates — not a list, not a count, not a reason — R9.
  • Read-only, and actionless. The detail carries no action at all — its only control is back, because it is a screen in the tree and not an overlay — R1, R28, R29.
  • Nothing frames a human's change as an error — R2.
  • The panel has a line budget and never grows to fit content. Absences are said, never padded.
  • Uppercase is for LABELS only; corners never exceed 5 px.

Section A — Phase 2: the shared full-screen drawing viewer

One viewer for every drawing in ops2, opened by tapping a drawing anywhere. It replaces the line plate's current side-panel enlargement — it is not a SidePanel: a drawing wants the whole viewport, not 520 px beside the work. It is a screen in the tree, not an overlay (R29): back at the leading edge naming the line it returns to, plus the standard edge-swipe. Escape still works — a keyboard convenience, not the navigation model.

Section B — Phase 3b: the panel, in every state

The panel sits between the specification (or the units block) and the price — the editor's own order. It is the console's existing lp-panel object with one addition: when there is a detail to open, the whole panel is a button and carries a chevron. Three fact lines when the platform made the choice; two when a person did — the owner's "far less rich in details" said by having fewer lines, never by padding three with absences.

Section C — the detail slide-out

The console's existing SidePanel: a right-hand slide-out at the desk, full screen on the phone. Reading order is the requirement → what is unusual about this line → the ladder, so the news is never below the routine. It scrolls; only the panel has a budget. There is no action in it — no footer, no CTA. Its one control is back: R29 puts this screen in the tree (projects → project → line → why this product), so it carries the same back control and the same edge-swipe gesture as every other ops2 screen. Switching products is deferred (R28): a button would imply a product is already selected to change to, and this surface deliberately offers no such thing.
